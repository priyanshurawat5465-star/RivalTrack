# RivalTrack — E-Commerce Competitor Sentiment & Defect Analysis

RivalTrack is a machine-learning project for collecting and analyzing e-commerce product reviews. Its goal is to support sentiment analysis and aspect/defect analysis through a review-scraping pipeline, text preprocessing, machine-learning models, and an interactive Streamlit dashboard.

> **Current repository status:** The latest commit history shows work on the NLP pipeline, asynchronous live review scraping, and Layer 1 ensemble training with 5-fold out-of-fold (OOF) predictions. A Layer 2 meta-learner and several advanced dashboard features remain on the roadmap. Update this README as implementation and validation progress.

## Features

### Review collection
- **Asynchronous live scraper:** `src/live_scraper.py` is intended to extract reviews from supported e-commerce pages using Playwright.
- **Historical scraper:** `src/spider.py` provides the earlier Playwright-based collection workflow.
- **Fallback handling:** The live scraper is described in the project history as including fallback-cache handling. Platform compatibility and anti-bot behavior should be validated against each target site.

### NLP preprocessing
- **Text normalization:** `src/nlp_pipeline.py` handles text preprocessing for downstream modeling.
- **Negation preservation:** The pipeline is designed to retain important negations such as “not” and “didn't,” which can change sentiment or defect meaning.
- **E-commerce terminology:** A custom jargon dictionary is used/planned to normalize common review expressions.
- **Aspect candidate extraction:** spaCy part-of-speech tagging is used/planned to help identify candidate product aspects.

### Machine-learning pipeline
- **Layer 1 base learners:** `src/train_layer1_oof.py` trains the first-layer models: calibrated LinearSVC, Multinomial Naive Bayes, and LightGBM.
- **5-fold OOF predictions:** The training workflow generates out-of-fold predictions intended for training a second-level model while reducing leakage between base-model training and meta-model training.
- **Baseline workflow:** `src/train_baseline.py` is retained as a legacy baseline script.
- **Model artifacts:** Trained models, vectorizers, and OOF data are stored under `models/` when generated by the relevant scripts.

### Dashboard
- **Streamlit interface:** `app.py` is the dashboard entry point.
- The project description includes a single-sentence test console, preprocessing inspection, corpus metrics, and defect-distribution visualizations. Confirm each view against the current implementation before presenting it as production-ready.

## Requirements

- Access to the target review pages for live scraping

## Installation

### 1. Clone the repository

```bash
git clone <YOUR_REPOSITORY_URL>
cd RivalTrack
```

Replace `<YOUR_REPOSITORY_URL>` with the repository's clone URL.

### 2. Create and activate a virtual environment (recommended)

**Windows PowerShell**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

**macOS / Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install Python dependencies

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 4. Install Playwright Chromium

```bash
python -m playwright install chromium
```

### 5. Download the spaCy English model

```bash
python -m spacy download en_core_web_sm
```

If a command fails, check the Python version and dependency versions specified in `requirements.txt`.

## Usage

Run commands from the repository root unless noted otherwise.

### 1. Collect reviews

```bash
python src/live_scraper.py
```

This runs the live scraper's CLI entry point, if configured. Check the script's configuration for supported URLs, platform requirements, and output paths before running it. Website structure and access restrictions can change.

### 2. Run NLP preprocessing

```bash
python src/nlp_pipeline.py
```

This runs the NLP pipeline's entry point, if configured. Review the script to confirm its expected input file, output file, and whether it fits or only applies preprocessing to the vectorizer.

### 3. Train Layer 1 models and generate OOF predictions

```bash
python src/train_layer1_oof.py
```

The latest commit history describes Layer 1 learners as calibrated LinearSVC, MultinomialNB, and LightGBM, with 5-fold OOF prediction generation. Check the script's logs and output files to confirm that training completed successfully and that the saved OOF data matches the meta-learner's expected format.

### 4. Launch the dashboard

```bash
streamlit run app.py
```

Open the local URL printed by Streamlit in your terminal. Available dashboard functionality depends on the current implementation and on which data/model artifacts have been generated.

## Model Pipeline

The intended high-level workflow is:

1. Collect product reviews from supported sources.
2. Clean and normalize review text while preserving sentiment-critical negations.
3. Transform text into numerical features using the configured TF-IDF workflow.
4. Train Layer 1 base learners.
5. Generate 5-fold out-of-fold predictions for use by a second-level model.
6. Train and evaluate the meta-learner (planned).
7. Use the resulting model outputs in the dashboard.

### Layer 1 models

- **Calibrated LinearSVC**
- **Multinomial Naive Bayes**
- **LightGBM**

OOF predictions are useful for stacking because the meta-learner should be trained on predictions produced for examples that were not used to fit the corresponding base model. Ensure all preprocessing and feature-selection steps are fitted within each cross-validation training fold; otherwise, data leakage may still occur.

## Troubleshooting

### Playwright cannot launch Chromium

```bash
python -m playwright install chromium
```

Run the command in the same environment where the project's dependencies are installed.

### spaCy model is missing

```bash
python -m spacy download en_core_web_sm
```

### A script cannot find a CSV or model file

Run commands from the repository root and check the input/output paths configured in the relevant script. Generated files may not exist until the collection or training step has completed.

### Dependency or platform errors

Use a virtual environment and install dependencies from `requirements.txt`. If a package fails to install, check its supported Python versions and any platform-specific requirements.
